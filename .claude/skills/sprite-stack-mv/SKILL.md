# sprite-stack-mv — スプライトスタッキングで MV 素材を作る

## 技法の要点

物体を水平に輪切りにしたスライス（2D のドット絵）を下から順に重ね、1枚ごとに画面の上へ少しずつずらして描く。
全スライスを同じ角度だけ回転させると、3D モデルなしで「回る立体」に見える。どの画素もドット絵のままなので、
ピクセルアートの質感を保ったままカメラを回せるのが利点。

MV で効くのは次の3つ。

- **回転**：物体やカメラ（世界全体）を回す。小節単位でゆっくり回すと画面がもたない静かなパートでも動きが出る。
- **gap（スライス間隔）の伸び縮み**：拍で `gap` を広げて戻すと、蛇腹のように弾む。スタッキング特有の動きで、キックに合わせると分かりやすい。
- **コマ打ち**：`anim_fps: 12`（2コマ打ち）にするとドット絵らしいカクつきになり、JIZURA の既定のコマ打ちとも揃う。

## 進め方

道具は `scripts/spritestack.py` の1本（Python 3.9+、Pillow、numpy。動画は ffmpeg）。
以下 `SS` は `python3 <このスキルのフォルダ>/scripts/spritestack.py` のこと。

1. **聞くこと**：曲の BPM と尺、画面比と解像度、何を回したいか（物・文字・キャラ画像）、単体で完成させるか他の映像に重ねる素材か。
   BPM が分からなければ仮の値で作り、後で `bpm` と `offset` を直すだけで済むと伝える。
2. **モデルを作る**（[references/formats.md](references/formats.md) の「モデル」）。
   入手経路は4つ：JSON で部品を組む／MagicaVoxel の `.vox`／スライスシート PNG／文字・画像を立体化。
   作ったら必ず `SS turntable model.json -o check.png --frames 8` で8方向を画像にして**自分の目で見る**。
   スタッキングは「どの面が見えるか」が直感とずれやすく（正面の模様が上のスライスに隠れる等）、見ないと気づけない。
3. **シーンを書く**（同ファイルの「シーン」）。数値はすべて式で動かせる。`b` が拍、`bar` が小節。
   `assets/example_scene.json`（単体で完結する例）か `assets/overlay_scene.json`（透過の重ね素材の例）を写して直すのが早い。
4. **静止画で確認**：`SS still scene.json -t 0,1,2,4 -o check.png`。構図・重なり・色を見てから動画にする。
   透過シーンは濃い灰色の上に並ぶ。物体が画面の端で切れていれば警告が出るので、出たら直す。
   動きの確認は `--end 4` などで短く書き出す。全尺の書き出しは最後に1回。
5. **書き出す**：`SS render scene.json -o out.mp4`。拡張子で形式が決まる。
   - `.mp4`：背景込みの完成映像（透過は持てないので、透過シーンは黒背景になる）。`--audio song.mp3` で曲を付けられる
   - `.mov`：ProRes 4444（透過あり）。Premiere / DaVinci / AE にそのまま置ける
   - フォルダ名：連番 PNG（透過あり、`stack_00000.png`…）
   - `.gif`：確認・共有用
   - 透過シーンから背景付きの確認用動画も欲しいときは、同じシーンを `--bg "#141428"` 付きで `.mp4` に書き出す（`still` でも使える）
6. **重ねる**（必要なとき）：`SS composite -o final.mp4 --fps 24 --audio song.mp3 下の層 … 上の層`。

速度の目安：1280×720・24fps・2コマ打ちで、8秒が約6秒。3分の曲でも数分で終わる。

## JIZURA と組み合わせる

JIZURA（歌詞PVの自動構成）の出力と重ねる場合、次の設定が噛み合う。

- JIZURA 側：「書き出し」の **中央を空ける（キャラクター用）** をオンにして、**透過PNG 前景／後景（ZIP）** で書き出す。
  歌詞が左右（縦長なら上下）の帯に寄り、中央が空く。空く幅は横長でおよそ中央の28%（21:9 は40%）、縦長は中央の高さ約34%。
- スタック側：`"background": "transparent"` にして、物体をその中央の空きに収める。`still` で幅を確認する。
  `fps`・`width`・`height` は JIZURA の書き出しと同じにし、`anim_fps` は JIZURA のコマ打ち（既定は2コマ打ち＝12）に合わせる。
- 合成：ZIP は展開しなくてよい。後景 → スタック → 前景 の順に重ねると、歌詞が物体の手前、背景の装飾が奥になる。

```sh
SS render scene.json -o stack_frames
SS composite -o final.mp4 --fps 24 --bg "#141428" --audio song.mp3 \
   jizura.zip:back stack_frames jizura.zip:front
```

JIZURA の透過 PNG は白〜グレーの単色素材（スタイルの配色や背景は入らない）なので、色は `--bg` とスタック側で作る。
JIZURA の配色・背景をそのまま使いたいときは、通常の MP4（中央を空けて書き出したもの）を一番下の層にして、
その上に透過のスタックを重ねる：`SS composite -o final.mp4 --fps 24 jizura.mp4 stack_frames`
（層に音が入っていても映像だけ使うので、曲は `--audio` で渡す）。

## うまく見せるコツ

- **内部解像度を小さく保つ**：`pixel_scale`（1ドットを何px で出すか）は 1080p なら 4〜8。モデルは 16〜48 ドット角、スライス 8〜40 枚が扱いやすい。
  大きく見せたいときはモデルを細かくするより `scale` を 2〜3 にする方がドット絵らしさが残る。
- **見下ろし角は `squash` と `gap`**：`squash` は地面の縦つぶし（1 で真上寄り、0.5〜0.6 で斜め見下ろし）。
  立っている板（文字・キャラ絵）は `squash` 0.5〜0.6 でないと正面が読めない。
- **立てる文字・画像は薄く**：`depth` は 1〜2。厚いと上のスライスの奥行きが下の行の抜きを埋めて、字が潰れる。
- **立てた文字は回さず、周回させる**：板は斜めになると読めないので、`face_camera` で正面を向けたまま円周上を動かす（書式は formats.md の「物体」）。
- **側面と上面の色分けは自動**：真上に別のボクセルがある画素は少し暗くなる（`wall`）。下のスライスほど暗くなる（`shade`）。
  輪郭線 `outline` を背景色に近い暗色で入れると、物体どうしが重なっても形が読める。
- **回しすぎない**：1小節で 45〜90° が見やすい。速い回転はサビやキメだけにする。向きを段階にしたいときは `yaw_steps: 16` などでレトロな見た目になる。
- **半透明は使わない**：スライスは重ね描きなので、半透明の画素は下が透けず、意図した見た目にならない。
- **AI 生成画像を素材にするとき**：1枚絵をそのまま輪切りにはできない。正面の絵を `upright` で立てるか、
  上から見た形を `layers` や `lathe` で描き起こす。色数を絞り、輪郭をはっきりさせた絵が向く。

## 使えないとき・注意

- 滑らかな 3D（遠近感のあるカメラ、ライティング、影の落ち方）が欲しい場合は Blender などの領分。この技法は平行投影の見下ろしに限られる。
- 既存の曲・キャラクター・ゲーム素材を使う場合、権利の確認は使う人の責任になる。モデルは自作か、利用が許された素材から作る。
